# windylane v0.5.0 — TaskCanvas

TaskCanvas completes windylane Phase 3 with tenant-scoped visual workflow
authoring, immutable publishing, durable execution, and node-level runtime
inspection. QueueFlow and EventForge remain the execution foundations for task
and webhook nodes.

## Highlights

- Visual workflow list, creation flow, and React Flow editor.
- Trigger, task, webhook, delay, and deterministic condition nodes.
- Publish-safe graph validation with structured errors.
- Atomic publishing and immutable sequential version snapshots.
- Durable workflow and node execution records in Postgres.
- QueueFlow task dispatch and EventForge signed webhook dispatch.
- Durable delays without goroutine sleeps.
- Cursor-paginated execution history and immutable-version timelines.
- Visibility-aware polling, execution cancellation, reconciliation, and stale
  claim recovery.
- Organization isolation across drafts, versions, executions, tasks, and
  webhook deliveries.
- Frontend, unit, race, API, Postgres, Redis, integration, smoke, and
  real-stack workflow coverage.
- Complete [TaskCanvas user and developer guide](../taskcanvas.md).

## Backend

Migrations added during the TaskCanvas phase:

- `0006_taskcanvas_workflows`: tenant-scoped workflow drafts, definitions,
  statuses, soft deletion, indexes, and active slug uniqueness.
- `0007_taskcanvas_workflow_versions`: immutable workflow snapshots,
  sequential per-workflow versions, and publish constraints.
- `0008_taskcanvas_workflow_executions`: durable workflow executions, node
  execution records, execution idempotency, external task/delivery links,
  reconciliation indexes, and the `workflow.node` EventForge event type.

TaskCanvas adds workflow CRUD, validation, publishing/version, execution list,
execution detail, and cancellation APIs under `/v1/workflows`. Execution
creation requires an organization-scoped `Idempotency-Key`; replaying the same
canonical request returns the same execution, while changed content returns
`409 idempotency_conflict`.

Postgres is authoritative for workflow and node state. Runnable nodes use
compare-and-set claims. QueueFlow and EventForge dispatch occur outside the
claim transaction with deterministic identities that prevent duplicate
external work. Unlinked claims receive a 30-second stale-claim lease before
safe reconciliation retry.

## Frontend

The dashboard adds:

- `/workflows` for tenant-scoped workflow history;
- `/workflows/new` for safe draft creation;
- `/workflows/{id}` for visual graph editing, node forms, validation,
  publishing, deletion, and immutable version inspection;
- `/workflows/{id}/executions` for version-aware execution start, status
  filters, and cursor pagination;
- `/workflows/{id}/executions/{executionId}` for deterministic node timelines,
  structured errors, payloads, external references, polling, and cancellation.

Published versions remain immutable. Editing a published workflow creates a
new draft, while historical execution pages retain the original snapshot's
labels, configuration, and topology. Legacy definitions without positions use
deterministic fallback positions.

## Reliability

- Publish is atomic and assigns the next version under database concurrency.
- Execution creation and initial node rows are transactional.
- Node claims use conditional updates.
- Task dispatch keys and webhook delivery IDs are deterministic.
- Reconciliation resumes pending/running executions after restart.
- A stale-claim lease recovers interrupted dispatch without racing active work.
- Delay timing is persisted, not held in process memory.
- Cancellation atomically closes the workflow execution and open nodes.
- QueueFlow and EventForge retry/recovery behavior remains unchanged.

## Upgrade notes

1. Back up production data using the normal deployment procedure.
2. Run migrations through `0008_taskcanvas_workflow_executions`.
3. If the dashboard was last installed before TaskCanvas M4, run `npm install`
   in `apps/dashboard`; M4 changed `package-lock.json` for React Flow.
4. Rebuild/restart the producer, workers, webhook worker, and dashboard.
5. Verify `/healthz`, `/readyz`, workflow creation, publish, and one execution.

There are no breaking QueueFlow or EventForge API changes. Public webhook
headers remain `X-Windylane-Event`, `X-Windylane-Delivery`,
`X-Windylane-Timestamp`, and `X-Windylane-Signature`.

## Known limitations

- No autosave or undo/redo.
- No collaborative editing.
- No workflow replay or manual node retry.
- No arbitrary code or arbitrary condition language.
- No live animated execution graph.
- Cancellation of already-started QueueFlow/EventForge work is best-effort.
- TaskCanvas is not a general-purpose distributed DAG scheduler.
- QueueLens analytics are not included and remain Phase 4 work.

## Dependency and security note

`npm audit --omit=dev` reports **3 high-severity production findings** in the
existing dashboard dependency tree:

- PostCSS: three advisories involving CSS stringification/source maps.
- sharp/libvips: inherited CVE findings.

Both paths are transitive through Next.js. npm reports that its available
forced fix would install `next@9.3.3`, an unsafe breaking downgrade. Do not run
`npm audit fix --force`. M5 added no package, and M6 intentionally makes no
dependency changes. Track remediation in a separate dependency-security
milestone, test a supported non-breaking Next.js upgrade, and do not describe
these findings as fixed in v0.5.0.
